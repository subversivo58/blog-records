
# Subversivo58 — blog-records

A Cloudflare Worker that provides the backend API for the Subversivo58 blog's record services.

The project receives, stores, and manages records submitted by the blog, using Cloudflare Workers and a D1 database.

## Main Features

The API provides three record services:

### Analytics

Receives and stores analytics data submitted by the blog.

### Feedback

Receives feedback submitted by visitors, including ratings and messages.

### Errors

Receives reports of problems submitted by visitors. These reports may describe different types of issues encountered while using the blog.

Errors are submitted by users; they are not automatically detected or collected by the application.

## API

The API is organized into public submission routes and administrative routes.

### Public Routes

These routes receive records from the blog and do not require JWT authentication.

| Method | Endpoint | Description |
|---|---|---|
| POST | `/v1/analytics` | Submit analytics records |
| POST | `/v1/feedback` | Submit visitor feedback |
| POST | `/v1/errors` | Submit problem reports |

### Administrative Routes

These routes require a valid JWT in the `Authorization` header.

| Method | Endpoint | Description |
|---|---|---|
| GET | `/v1/admin/analytics` | List analytics records |
| GET | `/v1/admin/analytics/:id` | Retrieve an analytics record |
| DELETE | `/v1/admin/analytics/:id` | Delete an analytics record |
| DELETE | `/v1/admin/analytics` | Delete analytics records |
| GET | `/v1/admin/feedback` | List feedback records |
| GET | `/v1/admin/feedback/:id` | Retrieve a feedback record |
| DELETE | `/v1/admin/feedback/:id` | Delete a feedback record |
| DELETE | `/v1/admin/feedback` | Delete feedback records |
| GET | `/v1/admin/errors` | List error reports |
| GET | `/v1/admin/errors/:id` | Retrieve an error report |
| DELETE | `/v1/admin/errors/:id` | Delete an error report |
| DELETE | `/v1/admin/errors` | Delete error reports |

Administrative listing endpoints support pagination.

Bulk deletion endpoints can delete all records or records within a specified date range.

## Authentication

Administrative endpoints are protected using JSON Web Tokens (JWT).

The implementation uses the EdDSA algorithm with Ed25519 keys.

Tokens are validated against the expected audience:

`blog-records`

The signing key is selected using the token's `kid` header. The corresponding Cloudflare Worker secret uses the `K_` prefix followed by the key identifier.

Public submission endpoints do not require JWT authentication.

## Integration

The blog communicates with this Worker through HTTP requests.

Public submissions are sent using the `POST` method. Administrative operations use authenticated requests with a JWT bearer token.

The API accepts requests from the official Subversivo58 blog origin:

`https://subversivo58.github.io`

## Database

The project uses Cloudflare D1 for persistent record storage.

The database is accessed through the `DB` binding configured in `wrangler.toml`.

The database stores the records received by the Analytics, Feedback, and Errors services.

## Configuration

The Worker is configured through `wrangler.toml`.

The configuration defines:

- Worker name: `blog-records`
- Main entry point: `BlogRecords.mjs`
- Compatibility date
- Observability
- D1 database binding: `DB`

## Purpose

This project provides a centralized backend for collecting and managing records generated by the Subversivo58 blog.

It separates record storage and administrative operations from the blog frontend while keeping public submissions independent of administrative authentication.
